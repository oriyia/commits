# Состав коммита

## Чего не класть

Проверки проекта перед коммитом обычно не пускают секреты и артефакты сборки по шаблонам
(`.env`, ключи, `node_modules/`, `build/` и т. п.), файлы агента и его память (`CLAUDE.md`,
`.claude/`, `memory/`) и манифест без lock-файла. Суждение нужно для того, что в шаблоны не
попадает:

| Что | Как быть |
|---|---|
| Следы работы: временные скрипты, заметки, вывод команд, `*.orig`, `*.rej`, патчи, снимки экрана | Удалить или держать во временной папке вне проекта |
| Отладка: печать, `breakpoint()`, закомментированный код, проверка, отключённая «на время» | Убрать до коммита |
| То, что пересобирается: отчёты тестов, покрытие, кэши, виртуальные окружения, собранные `.docx` и `.pdf` | Не в git; шаблон — в `.gitignore`, если это порождает проект у всех |
| Личные настройки редактора и инструментов | Скрыть через `.git/info/exclude`, не через `.gitignore`: тот виден всем и остаётся в истории |
| Секреты не по шаблону: токен в тесте, пароль в URL, ключ в примере конфига, настоящие персональные данные в фикстурах | Переменная окружения, заглушка, синтетические данные |
| Крупные двоичные файлы: данные, модели, архивы | Только по решению человека: git хранит их навсегда |
| Шум: файл изменён целиком ради трёх строк (концы строк, кодировка, BOM, автоформатер) | Вернуть исходный вид; нужное переформатирование — отдельным коммитом |

В коммит уже попало лишнее или секрет — `repair.md`.

## Документация к изменению

- Каждое изменённое имя — опцию, команду, переменную окружения, поле конфига, код ошибки, адрес
  API — найти: `git grep -n "<имя>"`. Найденное в `README.md`, `docs/`, `CONTRIBUTING.md`, примерах
  конфигов, справке `--help` — прочитать и поправить.
- Комментарий и docstring у изменённого кода — тоже документация.
- Поведение не изменилось (рефакторинг, тесты) — документацию ради галочки не трогать.
- Давняя неточность в документации, не связанная с изменением, — отдельный коммит.
- Документация не опережает код: описание того, чего ещё нет, ждёт коммита с кодом.
- Задание или спецификация, выданные проекту, не правятся: правки идут через того, кто их выдал.
