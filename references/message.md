Когда читать: формулируешь сообщение и сомневаешься; нужны примеры плохих и хороших сообщений; хук commit-msg отклонил сообщение.

# Сообщение коммита

## Тело

**Тело** — через пустую строку, строки до ~72 знаков, о том, **почему**: какая была проблема,
почему решено так и что отвергли, что знать тому, кто будет обновлять или откатывать (миграция,
несовместимость, порядок выкладки). Мелкому изменению хватает первой строки. Пять строк — предел,
а не норма; не хватает — значит, в теле пересказ, а не причина.

**Тело — не отчёт о сессии.** Перечня «что сделано» (добавил тест, поправил README, обновил
зависимость, прогнал проверки) в нём нет: это видно из diff и из `git log --stat`. Пункт перечня,
который не о том же изменении, — признак второго коммита.

**Читатель — человек без контекста сессии.** Не писать «как просили», «по итогам обсуждения», «по
замечаниям ревью», номера шагов плана, ссылки на чат и на файлы, скрытые от git (память, планы,
черновики). Ссылаться — на то, что есть у всех: путь в репозитории, хеш коммита, номер задачи на
сервере, если так принято в проекте.

## Примеры

| Плохо | Что не так |
|---|---|
| `Правки`, `WIP`, `Обновить код` | не сказано, что изменилось |
| `fix export` | то же, и без кириллицы |
| `Исправить баг` | какой — не понять без diff |
| `Изменения в parser.py и utils.py` | файлы видны и так; суть не названа |
| `Исправления по замечаниям ревью` | процесс, а не суть; замечаний через год не найти |
| `Добавить экспорт в Excel, поправить README и обновить зависимости` | три изменения — три коммита |
| Тело «— добавлен класс Exporter; — написаны тесты; — обновлён README; — проверки прошли» | перечень сделанного вместо «почему» |

Хорошо:

```
Не терять последнюю строку CSV без перевода строки в конце

Разбор читал файл построчно и отбрасывал хвост после последнего \n,
поэтому выгрузки из бухгалтерии теряли итоговую строку. Теперь хвост
разбирается как обычная строка.
```

```
Вынести проверку прав доступа в модуль access

Поведение не меняется. Следующим коммитом проверка понадобится в API
отчётов; копия в двух обработчиках со временем разошлась бы.
```

## Как записать и что делать, если хук отклонил

Многострочное сообщение: `git commit -m "<первая строка>" -m "<абзац>"` — каждый `-m` становится
абзацем; или `git commit -F <файл>`, файл — во временной папке вне рабочего дерева.

**Хук commit-msg отклонил сообщение** — он пишет, какое правило нарушено. Исправить сообщение
(сократить первую строку, убрать из тела перечень, убрать подпись) и выполнить `git commit` снова:
индекс сохранился. Длинная первая строка часто значит, что в коммите два изменения, — тогда
`git restore --staged <пути>` и резать.
